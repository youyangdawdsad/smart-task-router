# 语音通知中继（Voice Notification Relay, VNR）

## 概述

语音通知中继模块解决的核心问题是：**电脑端完成工作后，如何通过有语音能力的设备播报结果**。

在 v2.0 中，电脑端完成任务后只能通过 device_chat 返回文本结果。但用户可能不在电脑前（如在厨房、卧室），需要通过语音听到结果。VNR 模块让电脑端可以将结果发送给有语音能力的设备（手机、音箱、带屏设备），由这些设备播报结果。

## 核心问题

### 现有痛点

1. **电脑端无语音能力**：PC 无法直接播报语音
2. **结果只能看不能听**：用户必须看屏幕才能知道结果
3. **通知不及时**：用户不在电脑前时，不知道任务已完成
4. **语音设备未被利用**：手机、音箱等设备有语音能力，但未被 SIE 引擎利用

### 设计目标

1. **自动选择语音设备**：引擎自动选择最合适的语音播报设备
2. **多种播报方式**：支持 TTS 播报、通知推送、语音消息
3. **智能选择**：根据设备状态和用户位置选择最佳播报设备
4. **向后兼容**：不影响现有路由逻辑

## 架构设计

```
┌──────────────┐                    ┌──────────────┐
│   电脑端 PC   │ ──任务完成──►      │  语音中继器   │
│  (任务执行者)  │                    │  (VNR Core)  │
└──────────────┘                    └──────┬───────┘
                                          │
                                          ▼
                                   ┌──────────────┐
                                   │  设备选择器   │
                                   │  (Selector)  │
                                   └──────┬───────┘
                                          │
                          ┌───────────────┼───────────────┐
                          ▼               ▼               ▼
                    ┌──────────┐    ┌──────────┐    ┌──────────┐
                    │ 手机-01   │    │ 音箱-01   │    │ 带屏-01  │
                    │ (TTS)    │    │ (TTS)    │    │ (TTS+显示)│
                    └──────────┘    └──────────┘    └──────────┘
```

### 三大子模块

1. **语音中继器（VNR Core）**：接收任务完成事件，触发语音播报
2. **设备选择器（Selector）**：选择最佳语音播报设备
3. **播报执行器（Executor）**：向目标设备发送播报指令

## 语音播报触发

### 触发条件

| 触发事件 | 说明 | 播报优先级 |
|----------|------|------------|
| 任务完成 | 任务执行成功 | normal |
| 任务失败 | 任务执行失败 | high |
| 崩溃风险 | 检测到崩溃风险 | urgent |
| 用户请求 | 用户主动要求播报 | normal |
| 定时提醒 | 定时任务触发 | normal |

### 播报内容

播报内容根据事件类型自动生成：

| 事件类型 | 播报内容模板 |
|----------|--------------|
| 任务完成 | "任务 {task_name} 已完成。{result_summary}" |
| 任务失败 | "任务 {task_name} 执行失败。{error_message}" |
| 崩溃风险 | "警告：检测到崩溃风险。{risk_details}" |
| 用户请求 | "{user_specified_content}" |
| 定时提醒 | "{reminder_content}" |

### 播报格式

播报内容需要适合语音朗读：

```json
{
  "type": "voice_notification",
  "event": "task_completed",
  "task_id": "T-xxx",
  "task_name": "生成 Excel 报告",
  "result_summary": "报告已生成，包含 3 个工作表和 5 张图表",
  "tts_text": "任务生成 Excel 报告已完成。报告已生成，包含 3 个工作表和 5 张图表。",
  "priority": "normal",
  "timestamp": "ISO8601"
}
```

**关键字段**：
- `tts_text`：适合 TTS 播报的文本（去掉特殊符号、格式化内容）
- `priority`：播报优先级（urgent/high/normal/low）

## 设备选择机制

### 选择维度

设备选择器从以下维度评估候选设备：

| 维度 | 权重 | 说明 |
|------|------|------|
| 语音能力 | 0.35 | 是否有 TTS 能力，评分高低 |
| 设备状态 | 0.25 | 是否在线、电量、网络 |
| 用户接近度 | 0.25 | 用户可能在设备附近 |
| 播报质量 | 0.15 | 扬声器质量、音量 |

### 语音能力评估

| 设备类型 | TTS 能力 | 播报质量 | 说明 |
|----------|----------|----------|------|
| speaker | ✅ 高 | 高 | 专为语音设计，扬声器质量好 |
| display | ✅ 高 | 中 | 有语音+屏幕，可同时显示 |
| phone | ✅ 中 | 中 | 有 TTS，但扬声器一般 |
| pc | ❌ 无 | — | 无语音播报能力 |
| tablet | ⚠️ 低 | 中 | 有 TTS，但通常静音 |

### 设备状态评估

| 状态 | 评分 | 说明 |
|------|------|------|
| 在线 + 充电中 | 1.0 | 最佳状态 |
| 在线 + 电量 > 50% | 0.8 | 良好状态 |
| 在线 + 电量 20-50% | 0.5 | 可用但不理想 |
| 在线 + 电量 < 20% | 0.2 | 不推荐 |
| 离线 | 0.0 | 不可用 |

### 用户接近度评估

| 信号 | 评分 | 说明 |
|------|------|------|
| 设备正在使用中 | 1.0 | 用户肯定在附近 |
| 设备最近有交互 | 0.8 | 用户可能在附近 |
| 设备长时间无交互 | 0.3 | 用户可能不在附近 |
| 未知 | 0.5 | 默认评分 |

### 综合评分计算

```
voice_score = capability_score × 0.35 + status_score × 0.25 + proximity_score × 0.25 + quality_score × 0.15
```

选择 voice_score 最高的设备作为播报目标。

### 选择流程

```
任务完成事件触发
  → 获取所有在线设备列表
  → 过滤出有语音能力的设备（speaker/display/phone）
  → 对每个候选设备计算 voice_score
  → 选择 voice_score 最高的设备
  → 如果最高分 < 0.3，不播报（设备状态太差）
  → 向目标设备发送播报指令
```

## 播报方式

### 方式一：TTS 播报

通过设备的 TTS（Text-to-Speech）能力直接播报：

```json
{
  "type": "tts_speak",
  "device_id": "speaker-01",
  "text": "任务生成 Excel 报告已完成。",
  "priority": "normal",
  "volume": 0.8
}
```

**适用设备**：speaker, display, phone

### 方式二：通知推送

通过系统通知推送结果（设备显示通知，不播报语音）：

```json
{
  "type": "notification_push",
  "device_id": "phone-01",
  "title": "任务完成",
  "body": "Excel 报告已生成",
  "priority": "normal"
}
```

**适用设备**：所有设备

### 方式三：语音消息

通过 device_chat 发送语音消息（设备播放语音消息）：

```json
{
  "type": "voice_message",
  "device_id": "phone-01",
  "audio_text": "任务完成",
  "priority": "normal"
}
```

**适用设备**：phone, tablet

### 方式选择规则

| 条件 | 选择方式 | 说明 |
|------|----------|------|
| 设备有 TTS 能力 | TTS 播报 | 首选，直接播报 |
| 设备无 TTS 但有通知 | 通知推送 | 次选，显示通知 |
| 设备无 TTS 且无通知 | 语音消息 | 兜底，发送语音消息 |
| 所有方式都失败 | 记录日志 | 放弃播报 |

## 播报策略

### 优先级策略

| 优先级 | 播报行为 | 说明 |
|--------|----------|------|
| urgent | 立即播报，打断当前播放 | 崩溃风险等紧急情况 |
| high | 排队播报，等待当前播放完成 | 任务失败等重要情况 |
| normal | 排队播报，低优先级 | 任务完成等常规情况 |
| low | 延迟播报，空闲时播放 | 非紧急信息 |

### 去重策略

避免重复播报：

| 策略 | 说明 |
|------|------|
| 相同任务 ID | 同一任务的完成事件只播报一次 |
| 时间窗口 | 5 分钟内相同类型的事件合并播报 |
| 内容去重 | 相同内容不重复播报 |

### 失败重试

播报失败时的重试策略：

```
播报失败
  → 等待 5 秒
  → 重试 1 次
  → 如果仍然失败：
      → 选择次优设备
      → 重试 1 次
  → 如果所有设备都失败：
      → 记录日志
      → 降级为通知推送
```

## 播报内容生成

### 内容模板

根据事件类型选择模板：

| 事件 | 模板 | 示例 |
|------|------|------|
| 任务完成 | "任务{名称}已完成。{结果}" | "任务生成报告已完成。报告包含3个工作表。" |
| 任务失败 | "任务{名称}执行失败。{原因}" | "任务视频转码失败。文件格式不支持。" |
| 崩溃风险 | "警告：{风险描述}。{建议}" | "警告：内存使用率过高。建议关闭其他应用。" |
| 定时提醒 | "{提醒内容}" | "该吃药了。" |

### 内容优化

TTS 播报前优化文本：

| 优化项 | 规则 | 示例 |
|--------|------|------|
| 去掉特殊符号 | 移除 #、*、` 等 | "# 完成" → "完成" |
| 数字转文字 | 小数字转中文 | "3个" → "三个" |
| 缩写展开 | 常见缩写展开 | "e.g." → "例如" |
| 去掉路径 | 文件路径不播报 | "/home/user/file.txt" → "文件" |
| 截断过长内容 | 超过 200 字截断 | 长报告只播报摘要 |

### 内容长度限制

| 播报方式 | 最大长度 | 说明 |
|----------|----------|------|
| TTS 播报 | 200 字 | 过长影响体验 |
| 通知推送 | 100 字 | 通知有长度限制 |
| 语音消息 | 300 字 | 语音消息可稍长 |

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `voice_relay_enabled` | true | 是否启用语音中继 |
| `auto_select_device` | true | 是否自动选择播报设备 |
| `default播报方式` | "tts" | 默认播报方式 |
| `播报_priority` | "normal" | 默认播报优先级 |
| `dedup_window_ms` | 300000 | 去重时间窗口（5分钟） |
| `retry_interval_ms` | 5000 | 重试间隔 |
| `max_retry` | 2 | 最大重试次数 |
| `max_content_length` | 200 | TTS 播报最大内容长度 |
| `tts_volume` | 0.8 | TTS 播报音量 |

## 边界

- 语音播报依赖目标设备的 TTS 能力
- 设备选择基于评分，不保证选择"最佳"设备
- 播报内容经过优化，但 TTS 质量取决于设备引擎
- 播报失败不影响任务执行结果的返回
- 语音中继不替代 device_chat 主链路，仅作为补充
- 播报内容不包含敏感信息（如密码、token）
- 设备选择不考虑用户隐私偏好（如用户可能不想在音箱上播报）

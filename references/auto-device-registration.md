# 自动设备注册（Auto Device Registration, ADR）

## 概述

自动设备注册模块解决的核心问题是：**新设备登录小米账号后，如何自动接入 SIE 引擎，无需用户手动配置**。

在 v2.0 中，设备列表是静态的——用户需要手动告诉引擎"我有一台新手机"。随着用户拥有越来越多的小米设备（手机、平板、音箱、带屏设备等），手动管理设备列表变得不可行。

ADR 模块通过**自动发现 + 能力探测 + 动态注册**，让新设备上线后自动成为 SIE 引擎的可用节点。

## 核心问题

### 现有痛点

1. **设备发现依赖手动**：用户需要明确告知"我有新设备"
2. **能力信息不准确**：设备能力矩阵需要手动维护
3. **新设备无法参与路由**：新设备上线后不会自动成为路由目标
4. **设备类型识别缺失**：引擎不知道新设备是手机、平板还是音箱

### 设计目标

1. **零配置接入**：新设备登录账号后自动被发现
2. **能力自动探测**：自动识别设备类型和能力
3. **动态更新**：设备能力变化时自动更新矩阵
4. **向后兼容**：不影响现有设备的路由逻辑

## 架构设计

```
┌─────────────────────────────────────────────────────────┐
│                    SIE 引擎（PC 端）                      │
│                                                         │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐ │
│  │  设备发现器   │───►│  能力探测器   │───►│  注册管理器   │ │
│  │  (Discoverer)│    │  (Prober)    │    │  (Registrar) │ │
│  └─────────────┘    └─────────────┘    └─────────────┘ │
│         │                  │                  │         │
│         ▼                  ▼                  ▼         │
│  ┌─────────────────────────────────────────────────┐   │
│  │              设备能力矩阵（Device Capability）    │   │
│  └─────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
         │                  │                  │
         ▼                  ▼                  ▼
    ┌────────┐        ┌────────┐        ┌────────┐
    │ 手机-01 │        │ 平板-01 │        │ 音箱-01 │
    └────────┘        └────────┘        └────────┘
```

### 三大子模块

1. **设备发现器（Discoverer）**：监听在线设备列表变化，发现新设备
2. **能力探测器（Prober）**：探测新设备的类型和能力
3. **注册管理器（Registrar）**：将新设备注册到能力矩阵

## 设备发现机制

### 发现源

SIE 引擎通过以下方式发现新设备：

| 发现源 | 触发时机 | 说明 |
|--------|----------|------|
| MiClaw 在线设备列表 | 每次路由决策前 | 系统提供的 online_devices 列表 |
| device_chat 握手 | 新设备发起通信时 | 新设备首次调用 device_chat |
| 心跳响应 | 心跳检测时 | 心跳响应中包含设备信息 |
| 用户声明 | 用户主动告知 | "我有一台新平板" |

### 发现流程

```
SIE 引擎启动
  → 加载已注册设备列表
  → 开始周期性检查在线设备（默认 60 秒间隔）
  → 每次检查：
      → 获取当前在线设备列表
      → 对比已注册设备列表
      → 发现新设备（online_devices 中有，但未注册）
      → 触发能力探测流程
      → 探测完成后注册到能力矩阵
```

### 设备标识

每台设备有唯一标识：

```json
{
  "device_id": "v1:4:pc_f5164291e9e8f08295807941207305b9",
  "device_name": "DESKTOP-1K9ALRB",
  "device_type": "pc",
  "is_local": true
}
```

**关键字段**：
- `device_id`：系统分配的唯一 ID，不可变
- `device_name`：用户可读名称
- `device_type`：设备类型（phone/pc/tablet/speaker/display）
- `is_local`：是否为当前设备

## 能力探测机制

### 探测策略

新设备发现后，SIE 引擎通过以下方式探测其能力：

| 策略 | 方式 | 适用场景 |
|------|------|----------|
| 类型推断 | 根据 device_type 推断基础能力 | 所有设备 |
| 工具探测 | 尝试调用设备工具，根据响应判断能力 | 手机/PC |
| 心跳探测 | 心跳响应中携带能力信息 | 所有设备 |
| 用户声明 | 用户主动告知设备能力 | 特殊设备 |

### 类型推断规则

根据 `device_type` 自动推断基础能力：

| 设备类型 | 推断能力 | 说明 |
|----------|----------|------|
| phone | sms, call, camera, location, alarm, media, notification, contacts, screenshot | 手机标准能力 |
| pc | code, ide, file, browser, text, office, search, notification | 电脑标准能力 |
| tablet | calendar, media, notification, file, search, browser | 平板能力（无 sms/call） |
| speaker | media, notification, tts | 音箱能力（语音为主） |
| display | media, notification, tts, calendar, file | 带屏设备能力 |

### 工具探测流程

```
新设备注册
  → 根据 device_type 推断基础能力
  → 尝试调用设备工具验证能力：
      → 发送探测请求："请报告你的可用工具列表"
      → 设备响应：["sms", "call", "camera", ...]
      → 对比推断能力，更新能力矩阵
  → 记录探测结果
  → 如果探测失败，使用推断能力作为默认值
```

### 能力评分初始化

新设备的能力评分使用默认值：

```json
{
  "device_id": "phone-02",
  "device_type": "phone",
  "capabilities": ["sms", "call", "camera", ...],
  "capability_scores": {
    "sms": 0.95,
    "call": 0.90,
    "camera": 0.95,
    ...
  },
  "registration_time": "ISO8601",
  "last_probed": "ISO8601",
  "probe_status": "success"
}
```

## 注册管理

### 注册流程

```
能力探测完成
  → 检查设备是否已注册（按 device_id 查重）
  → 如果未注册：
      → 创建设备能力条目
      → 填入探测到的能力和评分
      → 添加到设备能力矩阵
      → 输出注册指示器
      → 通知用户："新设备 {name} 已接入"
  → 如果已注册：
      → 更新能力信息（如果探测到变化）
      → 更新最后探测时间
```

### 设备类型自动分类

SIE 引擎根据设备特征自动分类：

| 特征 | 判断条件 | 类型 |
|------|----------|------|
| 有 SIM 卡 + 通话能力 | device_type="phone" 或有 sms/call 能力 | phone |
| 有终端 + 代码执行 | device_type="pc" 或有 code/ide 能力 | pc |
| 大屏 + 无 SIM 卡 | device_type="tablet" 或屏幕 > 8寸 | tablet |
| 无屏 + 语音输出 | device_type="speaker" 或有 tts 能力 | speaker |
| 有屏 + 语音输出 | device_type="display" 或有 tts + 屏幕 | display |

### 动态更新

设备能力不是静态的，SIE 引擎支持动态更新：

| 触发条件 | 更新内容 | 说明 |
|----------|----------|------|
| 心跳响应变化 | 电量、网络、负载 | 实时更新 |
| 工具调用失败 | 降低能力评分 | 可靠性下降 |
| 用户声明变化 | 能力列表 | 用户主动告知 |
| 定期探测 | 完整能力矩阵 | 每 5 分钟重新探测 |

### 设备下线处理

```
设备下线（心跳超时或主动 bye）
  → 标记设备 offline
  → 从可用设备列表移除
  → 但保留能力矩阵条目（下次上线可快速恢复）
  → 如果设备 7 天未上线，清理能力矩阵条目
```

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `auto_discovery_enabled` | true | 是否启用自动发现 |
| `discovery_interval` | 60s | 设备发现检查间隔 |
| `probe_timeout` | 10s | 能力探测超时 |
| `probe_retry` | 3 | 探测失败重试次数 |
| `capability_update_interval` | 300s | 能力矩阵定期更新间隔 |
| `offline_cleanup_days` | 7 | 设备离线多久后清理条目 |
| `max_devices` | 20 | 最大注册设备数 |

## 边界

- 自动发现依赖 MiClaw 系统提供的在线设备列表
- 能力探测基于推断和验证，不保证 100% 准确
- 新设备注册后默认使用推断能力，评分可能不准确
- 设备类型自动分类可能误判（如平板被识别为手机）
- 自动发现不替代用户手动声明（用户声明优先级更高）
- 设备下线后保留能力矩阵条目，避免频繁注册/清理
